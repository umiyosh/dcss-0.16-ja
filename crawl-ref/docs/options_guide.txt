Crawlのオプションガイド
========================

このドキュメントでは、Dungeon Crawl Stone Soupの最新バージョンのすべてのオプシ
ョンについて説明します。行き詰まったり、正常に動作しないように見える場合は、
freenodeの##Crawl、またはhttp://crawl.develz.org/tavern/ のCrawlフォーラムで助
けを求めてください。

0-  オプションに関する一般事項。
============================

0-a     標準および追加のオプションファイル。
---------------------------------------------

Crawlは、次のリストの最初のファイルをオプションファイルとして使用します。
* settings/init.txt
* init.txt (Crawlディレクトリ内)
* .crawlrc (Unixホームディレクトリ内)

あるいは、次のコマンドラインオプションを使用して、そのファイルを使用するよう
Crawlに指示できます。
    -rc <file>

開始画面で、Crawlは、使用する初期化ファイルがある場合はそれを示します。

オプションファイル内に追加のファイルを読み込めます。
    include = <file>
その内容は、オプションファイルに直接記述されたものとして扱われます。既定では、
Crawlは読み込むファイルをsettings/ディレクトリから探しますが、次のコマンドライ
ンオプションで別のディレクトリを指定できます。
    -rcdir <dir>

外部オプションファイルにはいくつかの用途があります。 Crawlの一般的な外観(メッ
セージの色付け/抑制、およびインベントリスタイル)を迅速にカスタマイズできます。
より複雑なオプションマジック(通常はluaが含まれる)も、この方法で簡単に隠すこと
ができます。最後に、settings/ディレクトリには追加のオプションファイルがいくつ
かあります。これらにより、一部のオプションとモンスターグリフを古いバージョンの
デフォルトに設定できます。詳細については、デフォルトのinit.txtのヘッダーを参照
してください。

0-b     コマンドラインのオプション。
------------------------------------

別のオプションファイルに切り替えることなく、オプションに小さな変更を加える簡単
な方法は、コマンドラインオプション-extra-opt-firstまたは-extra-opt-lastを使用
することです。これにより、指定されたオプションが(それぞれ)オプションファイルの
先頭または末尾にあるかのようになります。例えば、

    -extra-opt-last wiz_mode=yes

新しいゲームはウィザードモードで開始されます。 -extra-opt-firstと
-extra-opt-lastは、同じコマンドラインで複数回使用できます。

0-c     オプションとその設定方法。
------------------------------------

Crawlオプションには、true/false値(ブール値)、任意の値、および値のリストという3
つの大きなタイプがあります。このドキュメントでは、通常、オプションはデフォルト
値(デフォルトがある場合)とともに説明されています。これは、それが上記のタイプの
どれであるかを説明する必要もあります。各オプションには、通常の使用方法について
の説明が必要です。ただし、使用するオプションはプレイスタイルによって異なり、場
合によってはオペレーティングシステムによっても異なることに注意してください。

オプションの設定に使用できるスタイルは2つあります。古典的な
name=value構文、1行に1つのオプション:
    remember_name  = true
    explore_greedy = false
    confirm_butcher= never

NetHackスタイルの複合オプション行:
    OPTION = remember_name, !explore_greedy, confirm_butcher:never

2番目のスタイルは、単純なオプションを数行で指定する場合に便利ですが、複雑な値
のリストを取るオプション(autopickup_exceptionsオプションなど)には使用
できません。

一部のオプションには引数としてパスが必要です。ここでは、システムに適したファイ
ルシステムパスを使用する必要があります。他のオプションは正規表現(正規表現)を受
け入れます。ここでは、単に通常の文字列を使用するか、提案された正規表現をニーズ
に合わせて調整するか、インターネットで正規表現構文を検索することができます。

チュートリアルおよびヒントモードでは、説明をわかりやすくするためにオプション設
定の一部が上書きされる場合があることに注意してください。これは次のオプションに
関係しており、チュートリアルゲームに対する強制設定は次のとおりです。
   clear_messages      = true
   weapon              = hand axe, for Berserkers in hints mode
そしてタイルについては、
   tile_tag_pref       = tutorial

0-d     リストオプション。
---------------------

多くのオプションには値のリストを含めることができます。これらのオプションのすべ
てではありませんが、ほとんどでは、カンマで区切って1行に複数の値を設定できま
す。このようなオプションでは、リセット、項目の追加、または項目の削除
が可能です。
   リスト末尾に値を追加:
      drop_filter += useless, enchant
   リスト先頭に値を追加:
      drop_filter ^= forbidden
   リストから値を削除（完全一致のみ）:
      drop_filter -= enchant
   リストをリセット:
      drop_filter = bad_item, dangerous_item
   リストを空にする:
      drop_filter =

「listopt = value」構文は、まずリストをクリアしてから、値を追加します。Crawlの
以前のバージョンでは、これは+=の同義語であり、リストをクリアするのは裸の
"listopt ="だけでした。

drop_filterなどの多くのオプションでは、追加と先頭に実質的な違いはありません。
ただし、message_colourなどの他のオプションでは項目の順序が考慮されます。これら
は、説明では「順序付きリストオプション」として示されます。ほとんどの場合、前の
項目が後の項目よりも優先されるため、+=は既存の一致(デフォルトを含む)に従います
が、^=はそれらをオーバーライドします。たとえば、一連のオプションでは次のよう
になります。
   message_colour  = cyan:hits
   message_colour ^= red:crimson
   message_colour += yellow:killer
「真紅のインプがあなたを襲います！」というメッセージが赤色で表示され、「キラー
ビーがあなたを攻撃します！」と表示されます。シアン色で表示されます。

0-e     エイリアスと変数。
------------------------------

長いオプション名には、次のようにエイリアスを定義できます。
    alias := long_option_name
たとえば、次のように使用します。
    ae := autopickup_exceptions
以降は「autopickup_exceptions」の代わりに「ae」を使用できます。
    ae += >uselessness, >inaccuracy

オプション値（変数）のショートカットも定義できます。たとえば、
    $useless := darkgrey
これは次のように使用できます。
    menu_colour += $useless:random uselessness

変数が変更されないようにするには、変数を定数にします。
    constant = useless

これは、インクルードされたファイルによって変数が変更されるのを防ぎたい場合
に便利です。

エイリアスと変数の使用法については、dat/defaults/standard_colours.txtおよび
dat/defaults/food_colouring.txtを参照してください。デフォルトのオプションはす
でにロードされているため、これらのファイルで定義されている変数を変更すると、独
自の構成ファイルにのみ影響することに注意してください。それらを変更したい場合
は、オプション自体をオーバーライドする必要があります。


1-  開始画面。
====================

次のオプションは、Crawlのゲームをすぐに開始するのに便利です。

name = Delilah
        設定されている場合、それがすべてのCrawlキャラクターに与えられる名前
        になります。

remember_name = true
        Crawlは、最後のキャラクターの作成に使用したオプション(種族、職業など)
        を記憶します。新しいキャラクターの開始画面でそれらを再利用できます。
        このオプションがtrueに設定されている場合、Crawlは使用した姓も
        記憶します。

        このオプションを使用し、種族および職業を選択した後で名前を入力する場合
        は、を入力する必要があります。最初の名前プロンプトで- remember_nameが
        設定されている場合は、名前プロンプトでEnterキーを押すだけで古い名前が
        再利用されます。

weapon += (short sword |...| unarmed | random | viable), <weapon>, ...
        （リストオプション）武器オプションを指定すると武器選択画面を省略できま
        す。トライデント、フレイル、カトラス、ロングソード、ウォーアックスは戦
        闘機と剣闘士のみに制限され、クォーターステーブは剣闘士に制限され、非武
        装は爪を持つ種族に制限されます。選択した職業に不正な選択が指定された場
        合、標準の武器プロンプトが表示されます。 「実行可能な」オプションで
        は、選択したキャラクターにとって「良い」武器の中からランダムに選択され
        ます。複数のオプションを指定すると、ゲームは指定されたリストから武器を
        ランダムに選択します。コンボオプションはこのオプションをオーバーライド
        します(また、このオプションによってオーバーライドされます)。

species += (Human |...| Vampire | random | viable), <species>, ...
        (リストオプション)通常の略語(Hu、HEなど)が機能します。「viable」は、職
        業が最初に選択された場合、特定の職業に対して実行可能な種族を選択しま
        す。複数の種族を指定すると、指定された種族からランダムに1つが選択され
        ます。コンボオプションはこのオプションをオーバーライドします(また、こ
        のオプションによってオーバーライドされます)。

background += (Fighter |...| Wanderer | random | viable), <background>, ...
        (リストオプション)ここでも略語(Fi、Wz、AKなど)を使用できます。同じ注意
        が「実行可能」にも当てはまります。実際に意味があるのは、種族オプション
        も設定されている場合のみです。複数の職業を指定すると、指定された種族か
        らランダムに1つが選択されます。コンボオプションはこのオプションをオー
        バーライドします(また、このオプションによってオーバーライドされます)。

combo += (HuFi . short sword | Human Monk | ...), <combo>, ...
        (リストオプション)種族、職業、および(該当する場合)武器の完全なセットを
        指定します。コンボに武器の選択が必要で、武器が指定されていない場合は、
        武器の選択を求めるプロンプトが表示されます。コンボは省略することも、完
        全に指定することもできます。複数のコンボが指定された場合、指定されたコ
        ンボの中からランダムに1つが選択されます。武器、種族、および職業オプシ
        ョンは、このオプションによってオーバーライドされます(オーバーライ
        ドされます)。

random_pick = false
        random_pickオプションはランダムにキャラクターを生成します。上記のオプ
        ション(武器および種族/職業オプション)は、必要に応じてオーバーライ
        ドされます。

good_random = true
        random_pickが使用される場合、種族または職業がランダムに設定される場
        合、またはキャラクター選択で記憶されたランダムな選択が実行される場合、
        ゲームは適切な(実行可能な)組み合わせのみを選択します。

restart_after_game = true/false
        restart_after_gameが設定されている場合、ゲームが終了すると、Crawlはメ
        インメニューに戻ります。このオプションは、タイルビルドではデフォルトで
        有効になり、他のビルドではデフォルトで無効になります。

restart_after_save = false
        ゲームが保存されたら、メインメニューに戻ります。 restart_after_gameも
        有効にしない限り、このオプションは効果がありません。

default_manual_training = false
        trueに設定すると、新しいキャラクターは自動モードではなく手動モードに設
        定されたスキルトレーニングから開始されます。

autopickup_starting_ammo = true
        設定すると、ゲーム開始時に、プレイヤーの開始弾薬タイプ(アースエレメン
        タリストの石やトランスミューターの矢を含む)の自動ピックアップが(\メニ
        ューに従って)強制的にオンになります。このオプションが設定されている場
        合でも、ゲームが開始されると、\メニューからこれらのアイテムの自動取得
        を無効にすることができます。

2-  ファイルシステム。
================

crawl_dir = <path>
        他のファイルを検索するときに相対パスとして使用されるパス。デフォルト
        は、Crawl実行可能ファイルを含むディレクトリです。

morgue_dir = morgue
        遺体安置所ダンプファイル(morgue*.txtおよびmorgue*.lst)および文字ダンプ
        ファイルが書き込まれるディレクトリ。

save_dir = saves
        セーブとボーンが保存されるディレクトリ。このオプションは、Crawlのコン
        パイルに使用される設定によっては無視される場合がありますが、公式の
        Crawlバイナリでは考慮される必要があります。

macro_dir = settings/
        macro.txtを読み取るためのディレクトリ。タイルゲームの場合、wininit.txt
        もここに格納されます。パス区切り文字で終わる必要があります。

sound ^= <regex>:<path to sound file>, <regex>:<path>, ...
        （順序付きリストオプション）メッセージが正規表現に一致した場合にサウン
        ドファイルを再生します。正規表現にはコンマやコロンを含めないで
        ください。例:
             sound += LOW HITPOINT WARNING:sound\sounds2\danger3.wav

3-  インターフェース。
==============

3-a     拾い上げと落とし。
--------------------------------

autopickup = $?!+"/%
        上記は既定のリストです。有効な記号は次のとおりです。
        )       武器
        (       飛び道具
        [       防具
        /       ワンド
        %       食料
        ?       巻物
        " or =  装飾品
        !       ポーション
        + or :  本
        |       杖
        \\       ロッド
        0       オーブ
        }       その他
        X       死体
        $       金貨

        アイテムを自動で拾うかどうかは、ゲーム内でCtrl-Aを押して切り替えられま
        す。拾う動作にはアイテム数にかかわらず1ターンかかります。アイテムのあ
        るマスへテレポートや瞬間移動をしても、自動では拾いません。

autopickup_exceptions ^= <pickup-regex, >don't-pickup-regex, ...
        (順序付きリストオプション)一致する項目を強制的に選択するか(先頭に<が付
        いている場合)、または決して選択されない(>が付いている場合)を指定する正
        規表現のセット。除外(>)は包含(<)よりも優先されるため、同じアイテムが除
        外と包含の両方に一致する場合、自動ピックアップの対象にはなりません。

        例:
             autopickup_exceptions += <curare-tipped needle
        飛び道具が「自動ピックアップ」オプションに設定されていない場合でも、自
        動ピックアップですべてのクラーレ先端の針を強制的に捕捉します。

        <>と一致式の間の空白は重要であるため、以下は機能しません。
             autopickup_exceptions += <   ebony casket

        autopickup_exceptionsは古いban_pickupを置き換えます。使用する
             autopickup_exceptions += >uselessness, >inaccuracy
        を使用するのと同じです
             ban_pickup += uselessness, inaccuracy

        正規表現の先頭に<または>が付いていなければ、 >が暗黙的に指定されるた
        め、上記のオプション設定は次のように記述することもできます。
             autopickup_exceptions += uselessness, inaccuracy

        複数のautopickup_exceptions回線を使用できます。いくつかの例:
             autopickup_exceptions += inaccuracy, scrolls? of paper
             autopickup_exceptions += immolation, curse (armour|weapon)
             autopickup_exceptions += uselessness, noise, torment

        例外のリストをクリアしない限り、非常に特殊な場合を除いて、ポーションの
        自動ピックアップ例外を設定する必要はありません。

default_autopickup = true
        falseに設定すると、自動ピックアップがオフになった状態でゲームが開始さ
        れます。ゲーム内でCtrl-Aを使用して自動ピックアップを切り替えること
        もできます。

pickup_thrown = true
        pickup_thrown = trueにすると、投擲／射撃した飛び道具を自動ピッ
        クアップで拾うことができるため、ハンタータイプにとっては非常に楽になり
        ます。自動ピックアップにはターンが必要ですが、敵対的なモンスターが視界
        にある場合はトリガーされないことに注意してください。

assign_item_slot = (forward | backward)
        アイテムを拾うと、通常はa-zA-Zのうち最初の空きスロットへ入ります（既定
        のforward動作）。backwardでは、最後に使われているスロットの次へ割り当
        てます。たとえば'a'と'c'にアイテムがある場合、
          assign_item_slot = forward なら次のアイテムは'b'へ、
          assign_item_slot = backward なら次のアイテムは'd'へ
        入ります。

        backwardでは、落としたり発射したりした後で拾い直したアイテムが、以前の
        スロットへ戻りやすくなります。

pickup_menu_limit = 1
        同じマスにこれより多くのアイテムがある場合、複数のアイテムを選択すると、
        アイテムごとにプロンプトが表示されるのではなく、メニューが表示されま
        す。ゼロの場合は、メニューを決して使用しないでください。負の場合は、代
        わりにitem_stack_summary_minimum - 1の値を使用します。

        オプションの価値に関係なく、ピックアップには常に1ターンかかることに注
        意してください。

drop_filter += <regex>, <regex>, ...
        (リストオプション)マルチドロップメニューでグローバル(解除)選択キー (',
        'または'-')を使用して項目を選択する場合、このオプションを使用して検索
        正規表現に一致する項目のみを選択することを選択できます。

        たとえば、神によって禁止されているアイテムをすばやく選択するには、次の
        ように使用できます。
             drop_filter += forbidden
        他の選択肢も同様に便利です。軸を除くすべての武器を定期的に犠牲にしたい
        場合は、次を使用します。
             drop_filter += axe, broadaxe

        drop_filterは、識別ステータスとチャンク情報が欠如していることを除い
        て、menu_colourが使用するのと同じキーワードと一致します。デフォルトは
        useless_itemです。

        drop_filterが設定されている場合、選択/選択解除キーを使用すると、フィル
        ター式に一致する項目の選択が設定/解除されます。

3-b     受動的目撃（検出または記憶された実体）。
------------------------------------------------------------

detected_monster_colour = lightred
        検出されたモンスターにはこの色が与えられます。

detected_item_colour = green
        検出されたアイテムにはこの色が付けられます。

remembered_monster_colour = darkgrey
        見たことのあるモンスターのカラー。

3-c     ブランド化(アイテムとモンスターの強調表示)。
-------------------------------------------------

ブランド化とは、特定のモンスター（召喚獣など）やアイテムを、前景色と背景色の反
転などで特別に表示することです。選択肢は次のとおりです（OSと端末によっては機能
しないものがあります）。
   standout         -- 多くの場合reverseと同じ。underlineやdimの場合もある
   bold             -- 前景色を明るくするためにcolour指定で使われる
   blink            -- 背景色を明るくするためにcolour指定で使われる
   reverse          -- 多くの環境で機能する
   dim              -- 効果がない場合が多い
   underline        -- 多くの環境で機能する
   highlight:colour -- ブランド化したモンスターの背景を「colour」にする
最後の指定はhi:colourと省略できます。dos_use_background_intensityについては「
DOSとWindows（5-b）」を参照してください。

デフォルトでは、次の2つのアイテムブランドだけが有効で、reverseに設定されます。
   heap_brand, feature_item_brand
これらは、「なし」に設定することで非アクティブにできます。

friend_brand = hi:green
        友達に何らかの形でブランドを付けましょう。これは召喚者にとって非常に役
        立ちます。デフォルト設定では、友達には緑色の職業が表示されます。友達自
        体が緑の場合は、緑の上に黒として表示されます。

neutral_brand = hi:lightgrey
        ある意味、ブランド中立のモンスター。中立のモンスターのパスから抜け出す
        場合と、誤って殺してしまうことを避ける場合の両方に役立ちます。デフォル
        ト設定では、ダークグレーの職業でニュートラルが表示されます。ダークグレ
        ーのモンスターグリフはもうないので、これは正常に機能します。

stab_brand = hi:blue
        あなたがモンスターを刺すことに反対する神々もいます。特定の職業はモンス
        ターを刺すことに特化しています。さらに他のキャラクターは、モンスターが
        発見する前にモンスターを発見すると満足します。これらすべてのケースにお
        いて、'x'コマンドを使用せずに、キャラクターを認識していない(したがって
        刺されやすい)モンスターを識別するのに役立ちます。通常の'brand'オプショ
        ンがすべて適用されます。

may_stab_brand = hi:yellow
        モンスターがスリープ状態でなくても(混乱している、または気が散っている
        場合など)刺す可能性があります。このオプションでは、刺すことができる*か
        もしれない*モンスターというブランドを付けます。

heap_brand = reverse
        ブランドのアイテムの山(複数のアイテムまたはスタック)。

feature_item_brand = reverse
        アイテムに隠される階段、店、祭壇などの地形を強調表示します。この設定で
        は、そのマスのアイテムが地形シンボルに隠され、地形シンボルが強調表示さ
        れます。

trap_item_brand = reverse
        アイテムに隠される罠を強調表示します。この設定では、そのマスのアイテム
        が罠のシンボル(^)に隠され、罠のシンボルが強調表示されます。

3-d     レベルマップ機能。
----------------------------

level_map_cursor_step = 7
        Shift-direction使用時にレベルマップ上でカーソルが移動するマス数。

show_waypoints = true
        レベルマップ上に中継地点を示す数字を表示するかどうか(Ctrl-Wコマ
        ンドで配置)。

3-e     ビューポート表示オプション。
---------------------------------

ビューポートは、通常のプレイ中に表示されるマップの部分です。デフォルトではビュ
ーポートは33x17ですが、より大きな端末サイズを使用する場合は、これらのオプショ
ンを設定してゲームに大きなビューポートを表示することができます。(これらのオプ
ションはDOSでは完全には利用できません。)

これらのオプションはいずれもゲームプレイに影響しません。特に、キャラクターの視
線はこれらのオプションの影響を受けません。

view_max_width = 33 (max 81)
        ビューポートの最大幅を設定します(デフォルトは33)。これを大きくすると、
        Crawlはより大きな端末でより広いビューポートを表示できるようになりま
        す。これはタイルでは無視され、ビューポートは常に利用可能なすべてのスペ
        ースを使用します。

view_max_height = 21 (max 71)
        view_max_widthと似ていますが、ビューポートの最大高さを設定します。タイ
        ルでは、この値は、スペースがビューポートではなくメッセージ領域に影響を
        与え始めるタイミングを設定するために使用されます。メッセージ領域が
        msg_max_heightに達すると、残りの領域がビューポートに移動します。パフォ
        ーマンス上の理由から、より小さいビューポートが必要な場合は、ウィンドウ
        サイズを小さくするか、メッセージ領域を大きくしてください。

* 大きなビューポートを使用すると、ゲームの速度が低下する可能性があることに注意
  してください。

view_lock_x = true
        プレイヤーキャラクターをビューポート内で水平方向の中央に配置し、PCの動
        きに合わせてビューポートを継続的にスクロールします。これが設定されてい
        ない場合、プレイヤーキャラクターはビューポート内で水平に移動でき、キャ
        ラクターの視線が左端または右端に達した場合にのみビューポートがスクロ
        ールします。

view_lock_y = true
        キャラクターをビューポート内で垂直方向の中央に配置します。

view_lock = true
        view_lock_xとview_lock_yの両方を設定するエイリアス化オプション。

center_on_scroll = false
        これが設定されている場合、ビューポートはスクロールするたびにプレイヤー
        キャラクターを中心に配置されます(view_lock_xおよびview_lock_yが設定さ
        れている場合、このオプションは無関係です)。

symmetric_scroll = true
        これを設定すると、スクロールの原因となったキャラクターの動きと一致する
        方法でビューポートがスクロールします。

        説明のために、PCがビューポートの下端にあり、水平方向の中心近くにあると
        します。ここで、PCが斜め下と右に移動し、ビューポートが強制的に1行上に
        スクロールします。 symmetric_scrollが設定されている場合、ビューポート
        もPCの斜めの動きに合わせて1列左にスクロールします。symmetric_scrollが
        設定されていない場合、ビューポートは水平方向ではなく上方向にのみスクロ
        ールします。 symmetric_scrollは、フリースクロールよりも方向感覚を失う
        可能性が低くなります。

        view_lockまたはcenter_on_scrollが設定されている場合、このオプションは
        関係ありません。

scroll_margin_x = 2
        スクロールを開始する左端または右端からの距離。デフォルトでは、PCの視線
        範囲が端から2マス以内にある場合、ビューポートはスクロールします。ゼロ
        に設定すると、LOS円がビューポートの端に達した場合にのみビューポートが
        スクロールします。

scroll_margin_y = 2
        上端または下端からスクロールを開始する距離。

scroll_margin = 2
        scroll_margin_xとscroll_margin_yの両方を設定するエイリアスオプション。

always_show_exclusions = true
        trueの場合、自動移動禁止エリアとその範囲を表示領域に表示します。この
        オプションの値に関係なく、除外は常にレベルマップ上に表示されます(Xでア
        クセス)。除外は地形のみモードでも表示されます(|でアクセス)。このオプシ
        ョンは、除外が常にビューポートとレベルマップの両方に表示されるタイルの
        ビルドでは効果がありません。

3-f     自動移動と探索。
-------------------------------

travel_delay = 20 (オンラインサーバーではデフォルト-1)
        explore_delayが設定されていない場合、各移動後に移動が待機する時間(ミリ
        秒)、および各移動後に自動探索が待機する時間。プラットフォームに応じて
        異なります。 -1に設定すると、移動の終わりにジャンプします。個々の移動
        は表示されません。

explore_delay = -1
        自動探索が各移動後に待つ時間（ミリ秒）。プラットフォームにより異なりま
        す。特にtravel_delay = -1かつ
        explore_delay = 20なら、自動探索の各移動は表示し、それ以外の移動は個々
        に表示しません。-1ではtravel_delayと同じ値を使います。

rest_delay = 0 (オンラインサーバーではデフォルト-1)
        各移動後に休憩が待機する時間(ミリ秒)。プラットフォームに応じて異なりま
        す。 rest_delay = -1に設定すると、休止中に表示が更新されなくなります。

travel_avoid_terrain = (shallow water | deep water)
        浅い水を通る移動を避けます。既定では無効です。マーフォークや永続的に飛
        行できるキャラクターも含め、水域を通る移動・探索を避けるには次のよ
        うにします。
             travel_avoid_terrain = shallow water, deep water
        真のリストオプションではないため、リセットや地形の個別削除は
        できません。

explore_greedy = true
        貪欲な探索は、レベルの探索に加えて自動ピックアップの対象となるアイテム
        を移動しますが、それ以外の点は通常の探索と同じです。自動ピックアップが
        オフになっている場合(Ctrl-A)、探索欲は無効になります。

explore_stop  = items,stairs,shops,altars,portals,branches,runed_doors
explore_stop += greedy_pickup_smart,greedy_visited_item_stack
explore_stop += greedy_sacrificeable
        (リストオプション)これらの条件のいずれかでExploreが停止します。このオ
        プションをどのように設定しても、移動を停止するものは探索も停止します。

        branches条件は分岐の入口で停止しますが、ほかの階段やポータルでは停
        止しません。

        注: runrest_ignore_messageはexplore_stopには影響しません。

        非貪欲探索を使用する場合、アイテムによって新しいアイテムが表示されると
        探索が停止します。貪欲探索を使用する場合、条件は次のように機能します。

        items:
            自動ピックアップの対象外のアイテムが表示されると停止します。

        greedy_items:
            自動ピックアップの対象となるアイテムが表示されると停止します。

        greedy_pickup:
            金貨を除き、プレイヤーが投げた・発射したものを含む自動取得対象のア
            イテムを拾った後で停止します。explore_stop_pickup_ignoreにより、特
            定のアイテムでは停止しないよう設定できます。

        greedy_pickup_gold:
            貪欲な探索中に自動的にゴールドを拾うと停止します。

        greedy_pickup_smart:
            greedy_pickupと似ていますが、インベントリにあるものと同種でないア
            イテムだけで停止します。投げた・発射したアイテムでは停止しません。
            停止したい場合はgreedy_pickup_thrownを追加します。

        greedy_pickup_thrown:
            投げた・発射したアイテムを拾うと停止します。greedy_pickupは元から
            停止しますが、greedy_pickup_smartは停止しません。
            explore_stop_pickup_ignoreはこの条件に影響しません。

        greedy_visited_item_stack:
            プレイヤーがこれまで知らなかったアイテムのスタックを訪問すると、ス
            タックに自動ピックアップの対象となるものが何も含まれていない場合で
            も停止します。

        greedy_sacrificeable:
            神へ捧げられるアイテムを含むスタックを訪れると停止します。

        glowing_items:
            itemsと同様ですが、光る・ルーン入り・刺繍入りなどのアイテムだけを
            対象にします。

        artefacts:
            itemsと同様ですが、アーティファクトだけを対象にします。

        runes:
            itemsと同様ですが、ルーンだけを対象にします。

explore_stop_pickup_ignore += <regex>, <regex>, ...
        (リストオプション) explore_stopにgreedy_pickupまたは
        greedy_pickup_smartが設定されている場合、リスト内の正規表現のいずれか
        に一致するアイテムを選択しても自動探索は停止しません。

        このオプションは、プレイヤーが投げたアイテムには影響しません。

explore_wall_bias = 0
        自動探索が部屋の周囲や隅の発見をどの程度優先するかを調整します。値を高
        くすると、自動探索は壁に隣接するマスを訪問することをより優先します。
        0では、まったく有利になりません。

explore_improved = false
        trueに設定すると、exploreは自動探索中のジグザグを軽減しようとします。
        平均すると、ターン数が約0.9%増加し、場合によっては実際にわずかに速度が
        向上し、ターン数が最大5%増加する場合もあり、病的なケースでは13%
        増加します。

auto_sacrifice = false
       trueでは自動探索中に対象アイテムを自動で捧げます。before_exploreでは、
       自動探索を始めるとき捧げられるアイテムの上に立っていれば自動で捧げま
       す。promptでは捧げる前に確認します。prompt_ignoreでは自動で捧げません
       が、捧げず探索を続けようとすると、そのアイテムを無視するか確認します。

       explore_stopにgreedy_sacrificeableが含まれていない場合、このオプション
       は効果がありません。

travel_key_stop = true
        trueに設定すると、キーを押すと移動が停止します。

tc_reachable      = blue
tc_dangerous      = cyan
tc_disconnected   = darkgrey
tc_excluded       = lightmagenta
tc_exclude_circle = red
        上の5項目はレベルマップ（'X'）の色を設定します。
          reachable:
              レベルを離れず安全に到達できるマス
          dangerous:
              罠などを通らないと到達できないマス
          disconnected:
              レベルを離れないと到達できないマス
          excluded:
              移動除外（'e'）の中心
          exclude_circle:
              移動除外の中心以外の範囲

runrest_ignore_message += <regex>, <regex>, ...
runrest_stop_message += <regex>, <regex>, ...
        (リストオプション)これらを使用して、メッセージが移動や休憩を強制的に中
        断するかどうかを決定します。これらはメッセージテキスト全体と照合されま
        す。部分文字列の一致をメッセージチャネルに制限するには、部分文字列の前
        にチャネル名とコロンを付けます(メッセージチャネルに関する下記のセクシ
        ョン3-lを参照)。たとえば、天罰に見舞われたときに自動移動を中止したい
        場合は、次のように使用できます。
             runrest_stop_message += god:wrath finds you
        または、有効期限が切れる呪文を更新するように自分に通知するには、次のよ
        うにします。
             runrest_stop_message += Your transformation is almost over
             runrest_stop_message += You are starting to lose your buoyancy
        または、一部のメッセージを明示的に無視することもできます。
             runrest_ignore_message += pleased with you,exalted

        デフォルトでは、モンスターの会話やダンジョンのノイズはすでに走行や休憩
        を妨げないことに注意してください。

        複数の回線を使用することもできます。無視メッセージと停止メッセージの両
        方で最も早く一致したものが、後の行をオーバーライドします。ファイル
        runrest_messages.txtには、多数のデフォルト設定が含まれています。

        いずれかのオプションをリセットすると、両方のオプションがリセッ
        トされます。

        runrest_ignore_messageは、explore_stopの停止内容には影響を与えないこと
        にも注意してください。

interrupt_<delay> += <activity_interrupt_type>, <activity_interrupt_type>, ...
        （リストオプション）特定のきっかけで遅延中の行動を中断しないよう設定し
        ます。delayの一覧はdelay.ccのdelay_names、割り込み種別は
        activity_interrupt_namesにあります。たとえば次の設定では、モンスターを
        感知しただけでまだ認識していない場合、自動移動を中断しません。
            interrupt_travel -= sense_monster

runrest_safe_poison = <% of hp>:<% of mhp>
        runrest_safe_poison = x:yとすると、予測される毒ダメージが現在HPのx%、
        かつ最大HPのy%未満なら無視します。ここでの移動はShift移動と休憩だけを
        指します。このオプションは1行だけ有効です。動作させるには、Crawlがダメ
        ージだけでなく「気分が悪い」というメッセージも無視する必要がありま
        す。たとえば、
             runrest_ignore_message ^= You feel.*sick
             runrest_safe_poison = 80:100
        が既定値です。

runrest_ignore_monster ^= <regex>:<distance>, <regex>:<distance>, ...
        （順序付きリストオプション）正規表現に一致するモンスターは、プレイヤー
        との距離が指定値未満の場合だけ行動を中断します。たとえば、
             runrest_ignore_monster ^= fish:3
        とすると、big fishとgiant goldfishは距離が3以上なら移動、探索、休憩を
        妨げません。複数の式に一致する場合は、最初に一致した距離を使います。

rest_wait_both = false
        rest_wait_bothがtrueに設定されている場合、休憩はHPとMPのどちらかが回復
        した場合ではなく、両方が完全に回復した場合にのみ停止します。

        (リストオプション)このリストに含まれる探索中に、睡眠中または静止してい
        るモンスターに遭遇すると、このモンスターを中心に移動除外が自動的に設定
        されます。つまり、自動探索によってその視界に入ることはありません。モン
        スターが死亡するか、視界に入っている間に起動した場合、この除外は再び自
        動的に削除されます。

sort_menus = [menu:](true | false | auto:X)[:sort_order]
        インベントリおよびピックアップメニューでアイテムを並べ替えるかどうか、
        および並べ替える方法を制御します。

        sort_menus = false (デフォルト)の場合、アイテムは並べ替えられず、在庫
        レターごとに(または床にアイテムが積み上げられている順序で)並
        べられます。

        sort_menus = trueの場合、アイテムは指定されたsort_orderに従って並べ替
        えられます。
             デフォルトは、quired、basename、qualname、curse、qtyです。

        sort_menus = auto:Xの場合、同じカテゴリに少なくともX個のアイテムがあれ
        ば、アイテムは並べ替えられます。例えば：
             sort_menus = auto:5
        少なくとも5つのアイテムを持つアイテムクラスを並べ替えます。たとえば、
        ポーションが4種類ある場合はソートされませんが、5種類ある場合はソー
        トされます。

        sort_menusオプションでソート基準を次のように明示的に指定できます。
             sort_menus = true : art, basename, qualname, curse, qty

        2つの項目が異なる場合、最初の並べ替え基準に基づいて比較されます。した
        がって、上記のsort_menus行では、2つの異なる項目のうち1つだけが既知のア
        ーティファクトである場合、それが最初にリストされます。そうでない場合(
        両方またはどちらもアーティファクトでない場合)、ベース名が異なる場合
        は、ベース名を使用してアルファベット順に比較されます。基本名が同じでも
        修飾名が異なる場合は、それらの修飾名が比較されます。

        利用可能な並べ替え基準は次のとおりです。

        * basename: アイテム種別の名前です。「+0 robe」「embroidered robe」
          「Pony's cursed +2 robe」のbasenameはいずれも「robe」です。「brass
          ring」と「ring of fire resistance」はいずれも「ring」です。

        * qualname:冠詞(a/an/the)、数量、エンチャント、または呪いのステータス
          を含まないアイテムの名前。上記のローブの修飾名は、それぞれ「ロー
          ブ」、「刺繍ローブ」、「ポニーのローブ」です。上記リングの修飾名はそ
          れぞれ「真鍮リング」、「耐火リング」です。

        * fullname:これはメニューに表示されるアイテムの名前です(数量、
          呪いのステータスなどを含む)

        * dbname:説明にリンクされているアイテムの一意の内部名に基づいて並べ替
          えます。同じ説明の項目はグループ化されます。

        * curse: アイテムの既知の呪い状態。呪われていないアイテムを
          先に表示します。

        * equipped: 装備中のアイテムを先に表示します。

        * art:特定されたアーティファクトが最初に表示されます。

        * ego:識別されたエゴアイテムが最初に表示されます。

        * glowing: 未識別の光る・輝く・ルーン入りなどのアイテムを
          先に表示します。

        * identified: 識別済みのアイテムを同種の未識別アイテムより先に表示しま
          す。サブタイプまたはegoが判明すれば識別済みとして扱います。

        * qty:スタック可能なアイテム(巻物、ポーションなど)の数量

        * slot: インベントリのアイテム文字。床のアイテムには関係しません。

        * charged: 充填が残っていると判明している、または空と判明していないワ
          ンドを先に表示します。ほかのアイテム種別には関係しません。

        次のように1つ以上の並べ替え条件の前に>を付けることで、降順で並べ替える
        ように要求できます。
             sort_menus = true : basename, >qty

        特定のメニューのみの並べ替えをリクエストすることもできます。
             sort_menus = pickup: true
        or
             sort_menus = inv: true
        (メニュータイプは、名前とコロンの間にスペースを入れずに、name:として指
        定する必要があります。)

        既定ではpickupメニューだけを「equipped, basename, qualname, curse,
        qty」で並べ替えます。drop、invなどほかのメニューはインベントリ
        文字順です。

        使用可能なメニューセレクターは次のとおりです。

        pickup: インベントリにないアイテムを扱う取得メニューや隠し場所検索など
        drop:   アイテムを落とすメニュー
        inv:    アイテムを落とす場合を除く、各コマンドのインベントリ一覧
        any:    すべてのメニュー。セレクターを省略した場合の既定値

        例えば、
             sort_menus = true : equipped, basename, qualname, curse, qty
        すべての着用/使用アイテムが最初に来ることを除いて、デフォルトと同じイ
        ンベントリとドロップメニューが生成されます。これは、'.'コマンドを使用
        して後続の項目を選択する場合に便利です。 2つ以上のセレクターに対して
        sort_menusを別々に定義した場合、最後に一致したものが常に優先されます。
        つまり、最後の設定として「any」が他の設定をオーバーライドします。

spell_slot ^= <regex>:<list of spell letters>
        (順序付きリストオプション、1行に1つの値)正規表現に一致する呪文を記憶す
        ると、リスト内の最初に使用可能な文字にそれ自体が割り当てられます。(リ
        スト内のすべての文字が、呪文が一致する正規表現ごとに占有されている場
        合、デフォルトの順序abc...xyzABC..XYZが使用されます。)呪文が複数の式に
        一致する場合、最初の式のみが考慮されます。

        例:
        * HasteをHへ配置する場合:
            spell_slot ^= Haste:H
        * Deflect Missilesを通常はr、rが使用済みならRへ配置する場合:
            spell_slot ^= Deflect:rR
        * 既定の呪文スロット割り当てを大文字へ変更する場合（ほかのspell_slot行
          より後に記述）:
            spell_slot += .*:ABCDEFGHIJKLMNOPQRSTUVWXYZ

item_slot ^= <regex>:<inventory letter>
        (順序付きリストオプション、1行に1つの値) spell_slotと同じインターフェ
        イスを使用します。さらに、item_slotオプションはアイテムが識別されたと
        きに適用されるため、識別されずに拾われた場合でも、適切な場所に移動でき
        ます。また、item_slotでは、spell_slotとは異なり、そこにすでにアイテム
        がある場合でも、アイテムが指定された場所に移動されます。ただし、そのア
        イテムが正規表現にも一致する場合は、プレイヤーが指定した次のインベント
        リ文字を試し、そのスロットが空かどうか、または正規表現と一致しないアイ
        テムがあるかどうかを確認します。

        trueに設定すると、自動探索または移動中にたどったパスが強調表示されま
        す。自動移動の経路が表示されている場合、地図のクリアコマンド(Ctrl-C)は、
        地図の代わりに経路を消します(もう一度押すと、通常どおりマップ
        がクリアされます)。

skill_focus = true
        trueに設定すると、スキルは、スキル画面で無効、有効、フォーカスの間を循
        環します。 falseに設定すると、有効と無効の間でのみ切り替わります。オプ
        ションを「トグル」に設定すると、スキル画面にトグルが追加され、ゲーム内
        の動作が変更されます。

monster_list_colour += <key>:<colour>, <key>:<colour>
monster_list_colour -= <key>
        (リストオプション)モンスターリスト内のモンスター名の表示に使用される色
        を変更します。有効なキーとそのデフォルトの色は次のとおりです。

           モンスターの態度:
             friendly       - green
             neutral        - brown（無関心）
             good_neutral   - brown（友好的）
             strict_neutral - brown（同族のスライム）

           敵対的なモンスターの脅威レベル:
             trivial        - darkgrey
             easy           - lightgrey
             tough          - yellow
             nasty          - lightred

         -=を使用してキーを削除すると、現在、キーの色をライトグレーに設定する
         のと同じ効果があります。

         TSO崇拝者の場合、このオプションに関係なく、攻撃が禁止されているモンス
         ターが「邪悪な色」 (デフォルトではマゼンタ)で表示されることに注意し
         てください。

view_delay = 600
        遠距離攻撃や魔法攻撃、視覚効果を伴う呼び出しなどのアニメーションの速度
        を制御します。

use_animations -= beam, range, hp, monster_in_sight, pickup, monster, player,
                  branch_entry
        追放時などの特殊なアニメーションを実行するかを制御します。既定ではすべ
        て有効で、次のカテゴリを個別に有効・無効にできます。

          beam             - ビーム呪文や遠距離武器のアニメーション。
          range            - 呪文の射程内にモンスターがいない場合、実際の射程を
                             示すオーバーレイを点滅させる。
          hp               - hp_warningで指定した水準を下回るダメージを受けた
                             とき、画面を赤く点滅させる。
          monster_in_sight - 危険なモンスターが見えている状態で休憩、走行、移動、
                             探索を試みたとき、モンスター以外の部分を点滅させる。
          pickup           - アイテム取得時のアニメーション。現在はルーンと
                             オーブのみ。
          monster          - モンスターが能力や呪文を使うときのアニメーション。
          player           - プレイヤーが能力や呪文を使うときのアニメーション。
          branch_entry     - 新しい分岐へ入るときのアニメーション。
                             現在はアビスとZotのみ。

force_more_message += <regex>, <regex>
        (リストオプション)ここで指定された正規表現を含むメッセージはすべて、
        -More-プロンプトを強制するため、本当に重要なイベントを強調表示するため
        に使用できます。構文はrunrest_ignore_message (3-g)と同じです。

cloud_status = true
        「クラウド」ステータスライトを表示するかどうか。デフォルトはtrueです
        が、タイルで遊んでいる場合は例外で、上に雲が表示されます。タイルでプレ
        イしている場合はデフォルトがfalseです。

3-i     色（メッセージとメニュー）。
-----------------

menu_colour ^= <match>:<colour>:<regex>, <colour>:<regex>, ...
        (順序付きリストオプション)これにより、指定された色で正規表現を含む行(
        インベントリ、メニュー、または検出画面の)が印刷されます。リストには複
        数のステートメントを含めることができ、また、複数のmenu_colour行を含め
        ることもできます。複数のmenu_colour行を使用する場合、_first_一致する正
        規表現の色が適用されます。色のリストについては、5-aの色のオプションを
        確認してください。

        一致により、どのリストが色付けの影響を受けるかを指定します。'any'を指
        定するか、<match>:部分を完全にスキップすると、すべてのリストが使用さ
        れます。一致に指定できる値は次のとおりです。
           ability       （A画面）
           description   （\\画面）
           equip         （[、(、)、"画面）
           help          （マニュアル）
           inventory     （インベントリと取得メニュー）
           pickup        （取得メニューのみ）
           shop          （店のメニュー）
           notes         （?:画面）
           resists       （%画面）
           spell         （ZおよびI画面）
           stash         （Ctrl-Fの結果）
           stats         （プレイヤーの能力値パネル）

        Crawlには、在庫の色付けを容易にするために定義されたいくつかのプレフィ
        ックスがあります。これらは定義順に次のとおりです。
           identified      （アイテムを完全に識別済み）
           known           （アイテムの種類を認識済み）
           unidentified    （アイテムの種類を未認識）

        アイテムには、基本タイプ(鎧、武器、杖など)の接頭辞も付けられます。

        以下は、サブタイプがわかっているアイテムにのみ適用されます。
           forbidden       （使用すると神の不興を買うアイテム）
           emergency_item  （緊急時に非常に役立つアイテム）
           good_item       （一般に有用なアイテム）
           dangerous_item  （使用すると危険なアイテム）
           bad_item        （一般に有害なアイテム）
           useless_item    （現在のキャラクターには役立たないアイテム）

        以下は、識別済みかどうかにかかわらず、特定の基本種別のアイテムだけに適
        用されます。
           inedible        （食べられない、または栄養を得られない）
           preferred       （草食・肉食など、キャラクターが好む食料）
           poisonous       （有毒な肉・死体）
           mutagenic       （変異性の肉・死体）
           contaminated    （得られる栄養が少ない肉・死体）
           rot-inducing    （腐敗を引き起こす肉・死体）

           equipped        （装備中のアイテム）
           artefact        （識別状況を問わずアーティファクト）
           melee           （ロッドや魔法の杖を含む近接武器）
           ranged          （遠距離武器）

        menu_colourの一致判定では、これらの接頭辞が実際のアイテム名の前へ追加
        されます。例:
           unidentified forbidden wand of draining (4)
           unidentified equipped artefact sparkling ring (left hand)

        同じ接頭辞を使用して、説明に一致する項目に関するプロンプトを強調表示し
        たり、autopickup_exceptionsを定義したりすることもできます。

        特定の接頭辞を含むすべての項目に色を付けたい場合は、次を使用します。
          menu_colour ^= lightgreen:poisonous

        使い古されたものに色を付け、呪われたアイテムを強調表示するには(他の、
        おそらくより重要なメッセージの色が一致する場合を除く)、次を
        使用します。
          menu_colour += inventory:lightred:equipped.* cursed
          menu_colour += inventory:green:equipped
          menu_colour += inventory:red: cursed

        識別されたアーティファクトに色を付けるには、試してください。
          menu_colour ^= inventory:white:( [-+] the)
        or
          menu_colour ^= inventory:white:identified.*artefact

        非常用品の使用を忘れて頻繁に死亡する場合は、次のことを試してください。
          menu_colour ^= inventory:cyan:emergency_item
          menu_colour ^= inventory:lightcyan:wand of (fire|cold|draining)

        menu_colourは、ゲーム内のメモの色付けにも適用できます('?: 'で読み取ら
        れます)。次の行では、レベルアップが白色で表示されます。
          menu_colour ^= notes:white:Reached XP level

message_colour ^= <colour>:<channel>:<regex>, <colour>:<regex>, ...
        （順序付きリストオプション）個々のメッセージの色を上書きします。たとえ
        ば、HP低下の警告を目立たせるには次のようにします。
             message_colour += yellow:LOW HITPOINT WARNING
        一致対象を特定のチャンネルへ絞ることもできます。
             message_colour += lightred:god:xom
        メッセージを表示したくない場合はミュートできます。
             message_colour += mute:You start resting

3-j     飛び道具。
-----------------

fire_items_start = a
        射撃／投擲するアイテムを選ぶ際、候補に含める最初のインベントリ項目を設
        定します。デフォルトはaです。

fire_order  = launcher, return
fire_order += javelin / tomahawk / stone / rock / net
fire_order += inscribed
        (順序付きリストオプション)射撃／投擲用に自動選択される項目の順序を制御
        します。項目はカンマで区切る必要があり、先に記述した項目ほど優先順位が
        高くなります。

        任意の位置にある項目は、同じ優先順位であることを示すためにスラッシュで
        区切ることができます。この場合、これらのいずれかに適合するインベントリ
        内の最初のアイテムが選択されます。

        'launcher'は、装備中の弓、クロスボウ、スリング、吹き矢筒などに適した
        矢弾を指します。射撃武器を装備していない場合は無視されるた
        め、通常は最初に指定します。'return'は、帰還
        属性を持つ(鑑定済みの)投擲武器を指します。

        'inscribed'は、「+f」の刻印が付いたアイテムを指します。刻印の詳細につ
        いては、Crawlのマニュアルの「刻印」セクションを参照してください。

(3-aのpickup_thrownも参照してください。)

3-k     メッセージチャネル。
-------------------------

Crawlは、メッセージウィンドウを使用してプレイヤーに通信します。すべてのメッセ
ージは、いわゆるチャネルの1つに属します。各チャンネルの動作はオプションで
変更できます

     channel.CHANNEL_NAME = (COLOUR | mute | default | on | off | plain)

現在、CHANNEL_NAMEは次のいずれかになります。
   plain           = 通常のテキスト
   prompt          = プレイヤーへの入力要求
   god             = 神からのメッセージ
   pray            = 通常の祈りに関するメッセージ
   duration        = 呪文や効果が切れるときのメッセージ
   danger          = キャラクターの生存に関わる重大な脅威
   food            = 食料に関する警告
   warning         = その他の警告
   recovery        = 病気、能力低下、毒からの回復
   talk            = モンスターの発言
   talk_visual     = 視界内のモンスターの行動
   timed_portal    = ポータルの時間切れ
   sound           = その他の音
   intrinsic_gain  = レベル、能力値、種族能力の獲得
   mutation        = 変異の獲得と消失
   monster_spell   = モンスターの身振りや呪文詠唱
   monster_enchant = モンスターへの魔法効果
   monster_warning = モンスターが視界に入ったときの警告
   friend_spell    = 友好的なモンスターのmonster_spell
   friend_enchant  = 友好的なモンスターのmonster_enchant
   friend_action   = 友好的なモンスターのその他の行動
   monster_damage  = モンスターの負傷状態
   monster_target  = 標的に指定されたモンスター(未使用)
   banishment      = アビスへの追放
   rotten_meat     = 肉、死体、血が腐るときのメッセージ
   equipment       = 装備の着脱
   floor           = 床のアイテムを見たときや踏んだときのメッセージ
   multiturn       = 防具の着脱や解体など、時間のかかる行動
   examine         = 周囲を調べたときのメッセージ
   examine_filter  = 周囲を調べたときの重要でないメッセージ
   diagnostic      = デバッグメッセージ
   error           = エラーメッセージ
   tutorial        = チュートリアルのメッセージ
   orb             = ゾットのオーブに関するメッセージ
   hell_effect     = 地獄の環境効果に関するメッセージ
   dgl_message     = 観戦者からのメッセージ(オンラインコンソールのみ)

チャンネルオプションは、
   mute      = このチャネルを表示しない(危険なので注意)
   default   = デフォルトの配色で表示する
   alternate = 別の色鮮やかな配色で表示する
   on        = defaultと同じ
   plain     = plainチャネルと同じ色にする
               (ただし、プレーン==ミュートの場合は、「ミュート」のような愚かな
               動作はしません)
   off       = plainと同じ

COLORには、セクション5-a (カラーオプション)で説明されている色のいずれかを指
定できます。

現在、マルチカラーチャネルはmonster_damageとgodのみです。他のすべてのチャンネ
ルはデフォルトでオンになっています。

3-l     碑文。
---------------------

刻印の詳細については、Crawlマニュアルの「刻印」セクションを参照してください。

autoinscribe += <regex>:<inscription>
        (順序付きリストオプション、1行に1つの値)説明に正規表現が含まれる項目は
        すべて、自動的に記録されます(自動ピックアップがオンになっている場合)。

        たとえば、次のように、重要な杖のチャージを誤って使用することを避けるた
        めに使用できます。
             autoinscribe += wand of heal wounds:!V

        メニューの色の接頭語(禁止など)もここで使用できます。例えば：
             autoinscribe += (bad|dangerous)_item.*scroll:!r
        特定された不良または潜在的に危険なスクロールを誤って読んでしまうこと
        を防ぎます。

        ほとんどの順序付きリストのオプションとは異なり、複数の一致するエントリ
        がすべて影響します。順序は碑文の順序のみを決定します。

show_god_gift = unident|yes|no
        元は1つだったアイテムに{god Gift}を追加します。 「unident」に設定され
        ている場合、アイテムのプロパティが完全に判明すると、アイテムはこのタグ
        を失います。この設定に関係なく、説明でアイテムの出所を確認できます。

3-m     マクロ関連のオプションです。
------------------------------

flush.failure = true
flush.command = false
flush.message = false
        これらはマクロを使用するときに便利です。これらのサブオプションの1つを
        trueに設定すると、入力バッファ全体がダンプされ、マクロが効果的に停
        止されます。サブオプションは次のとおりです。
           failure -- 呪文・能力が失敗したとき
           command -- ゲームが次のコマンドを取得しようとしたとき
           message -- ゲームがミュートされていないメッセージを出力したとき

additional_macro_file = path/to/filename
        macro.txtの後にロードするマクロファイルを追加します。複数の
        additional_macro_file行を持つことができます。

bindkey = [^D] CMD_BUTCHER
        マクロよりも低い操作レベルで、どのキーがどのコマンドを呼び出すかを変更
        します。マクロは(まだ)相互に呼び出すことができませんが、マクロはキーが
        変更されたコマンドを呼び出すことができるので便利です。構文は常に同じで
        す: [key]コマンドまず、角括弧内に使用するキーをリストします。^Xは
        Ctrl-Xを意味します。その後、そのキーにバインドされるコマンドに名前を付
        けます。ゲームの異なる領域で有効である限り、複数のコマンドを同じキーに
        バインドできます。つまり、1つはターゲットコマンド、もう1つはメインゲー
        ム用です。同様に、同じコマンドを異なるキーにバインドできます。使用可能
        なコマンドの完全なリストについては、keybind.txtを参照してください。

            enemy    - 名前のある敵対的なモンスターを表示する

        名前のあるモンスターには、ユニークモンスターやゴーストなどがあります。

        ウィンドウの幅と高さ(ピクセル単位)。ゼロに設定すると、ウィンドウのサイ
        ズが自動的に調整されます。

tile_map_pixels = 0
        ミニマップの1マスが占める最大ピクセル数。解像度が低く、インベントリ
        が小さすぎると感じる場合は、これを1に設定して、インベントリ用のスペー
        スを増やすことができます。欠点は、ミニマップをクリックして移動するのが
        はるかに困難になることです。ゼロに設定すると、ミニマップのサイズが自動
        調整されます。

tile_cell_pixels = 32
        ダンジョンビューのタイルの幅と高さ。タイルを最大限に美しく表示し、解像
        度を高くしたい場合は、これを48または64に設定します。ただし、タイルは画
        面上の表示領域に合わせて自動的に縮小されることに注意してください。

tile_filter_scaling = false
        tile_cell_pixelsと組み合わせて使用します。これをtrueに設定すると、テク
        スチャがフィルタリングされ、より滑らかですがぼやけたイメージ
        になります。

tile_force_overlay = false
        このオプションをtrueに設定すると、メッセージウィンドウが画面上部のオー
        バーレイとして強制的に表示されます。このオプションを使用する場合、
        tile_font_msg_sizeを小さくすると、同じ行数を維持したままオーバーレイが
        小さくなります。使用されていない画面領域がある場合は、view_max_height
        オプションを増やします。

tile_full_screen = false
        このオプションをtrueに設定すると、Crawlが全画面モードで起動します。

tile_font_crt_file  = VeraMono.ttf
tile_font_stat_file = VeraMono.ttf
tile_font_msg_file  = VeraMono.ttf
tile_font_tip_file  = VeraMono.ttf
tile_font_lbl_file  = Vera.ttf
        ローカルタイルの各画面領域で使用するフォントです。WebTilesでは代わりに
        tile_font_*_familyを使います。別のフォントを使う場合は、対応する*.ttf
        ファイルをdat/tiles/へ配置してください。
            crt  - マップ以外の画面（メニュー、メッセージ履歴など）
            stat - 能力値領域（HP、ACなど）
            msg  - メッセージ領域
            tip  - ツールチップ（マウスオーバー情報）
            lbl  - インベントリやメインマップのアイテム・モンスター名

tile_font_crt_family  = monospace
tile_font_stat_family = monospace
tile_font_msg_family  = monospace
tile_font_lbl_family  = monospace
        WebTilesの画面のさまざまなセクションで使用されるフォント。ローカルタイ
        ルの場合は、代わりにtile_font_*_fileを使用してください。

tile_font_crt_size  = 15
tile_font_stat_size = 16
tile_font_msg_size  = 14
tile_font_tip_size  = 15
tile_font_lbl_size  = 14
        上記の画面領域のフォントサイズ。ゼロ(デフォルト)に設定すると、サイズは
        画面サイズに基づきます。

tile_font_ft_light = false
        'light'フォントのヒンティングを選択します。

tile_show_minihealthbar = true
tile_show_minimagicbar  = true
        プレイヤーが怪我をしたり、魔法を消費したりすると、プレイヤータイルの上
        に体力と魔法のバーが表示されます。

tile_show_demon_tier = true
        タイル以外のビルドの場合と同様に、悪魔のタイルに、悪魔の中での階層(ま
        たは難易度のランク)を表すことを目的としたアイコンをオーバー
        レイします。

tile_water_anim = true
        無効にすると、液体のアニメーションが抑制されます。 WebTilesのデフォル
        トはfalseです。

tile_misc_anim = true
        無効にすると、祭壇や松明などのさまざまなもののアニメーションが抑
        制されます。

tile_realtime_anim = false
        有効にすると、タイルアニメーションはリアルタイムで実行され、プレーヤー
        のアクションに関連付けられません。このオプションはWebTilesでのみ使
        用できます。

tile_show_player_species = false
        有効にすると、通常の人形を使用して装備を表示する代わりに、種族にモンス
        タータイルを使用してプレーヤーが表示されます。

tile_layout_priority = minimap, inventory, gold_turn, command, spell, monster
        (順序付きリストオプション)このオプションを使用すると、画面の右側、統計
        領域の下に要素を配置する順序を制御できます。解像度が小さい場合、すべて
        を入れるのに十分なスペースがないため、最初の項目のみが配置されます。永
        久に表示したくない項目を削除することもできます。インベントリータブは常
        に一番下に配置されますが、最小サイズ(4行)で初期化されます。オプション
        行の前にタブを配置した場合、タブは引き続きその上に配置されますが、タブ
        が優先されるため、インベントリが最大サイズ(6行)まで拡張できない可能性
        があります。ミニマップは常に統計領域とタブの間に配置されます。記憶タブ
        とスキルタブもリストに追加できますが、デフォルトでは追加されません。

tile_display_mode = (tiles | glyphs | hybrid)
        ダンジョンのレンダリング方法を制御します。通常のタイル(デフォルト)を使
        用することも、グリフを使用してコンソールバージョンのように見せることも
        できます。グリフビューの上にアイコンをハイブリッドオーバーレイします。
        このオプションはWebTilesでのみ使用できます。

tile_level_map_hide_messages = true
tile_level_map_hide_sidebar = false
        レベルマップの使用時に非表示にする画面要素を制御します。これらのオプシ
        ョンは、WebTilesでのみ使用できます。

tile_player_tile = (normal | playermons | mons:<monster> | tile:<monster-tile>)
        playermonsに設定すると、通常の人形を使用する代わりに、種族のモンスター
        タイルを使用してプレーヤーを表示します。

        mons:<monster>形式では、指定したモンスターの基本タイルをプレイヤータイ
        ルに使います。たとえばmons:ijybならIjybのタイルを使います。モンスター
        名の空白もそのまま記述するため、mons:the royal jellyも有効です。

        形式tile:<player-tile>の値に設定されている場合、<player-tile>はプレー
        ヤータイルシート内のタイルの名前であり、このタイルをプレーヤータイルと
        して使用します。この形式は、ヒドラや大型の忌まわしいタイルなどの複数の
        タイルを持つモンスターの特定のバリアントタイル、またはCigotuviのモンス
        ターや独自のベースモンスターを持たないプレイヤーの変換などの特殊なタイ
        ルを使用する場合に最も役立ちます。タイル名はフルネームである必要があり
        ます。 mons_hydra_7。たとえば、多くの頭を持つヒドラタイルを使用するに
        は、tile:mons_hydra_7の値を使用します。タイル名は、ソースツリーフォル
        ダーのsource/rltilesファイルdc-mon.txt、dc-demon.txt、および
        dc-player.txtにあります。これらのファイルでは、タイル名は画像のファイ
        ル名の後の各エントリの2番目の単語にあり、照合では大文字と小文字は無視
        されます。モンスタータイル名は通常、mons_<モンスター-name>の形式です
        が、変換などの他のタイルは別の名前が付けられます。ツリー変換タイルの場
        合はtran_tree。

tile_weapon_offsets = (<x>,<y> | reset)
tile_shield_offsets = (<x>,<y> | reset)
        tile_player_tileでカスタムタイルを使用する場合、これらのオプションは、
        タイル内で武器または盾が描画される位置のピクセルx (水平)およびy (垂直)
        オフセットを設定します。 xオフセットとyオフセットは、-32から32までの整
        数である必要があります。負のx値は左に調整され、負のy値は上に調整されま
        す。 0,0では、武器はタイルの左側に描画され、0,0では、盾が右側に描画さ
        れます。武器のxオフセット。したがって、10 ～ 20 (タイルに応じて)と盾x
        オフセット-10 ～ -20を使用して、武器と盾の位置を交換できます。

        値「reset」を使用すると、luaを介したゲーム内タイルの変更に使用されてい
        る、以前に定義されたオフセットがクリアされます。

4-  キャラクターダンプ。
===================

4-a     保存。
---------------

dump_on_save = true
        trueに設定すると、ゲームの保存時にキャラクターダンプが自動的に作成また
        は更新されます。

4-b     アイテムとキル。
------------------------

キャラクターダンプまたは遺体安置所ファイルは、キャラクターがアクティブだった間
に死亡したすべてのモンスターのリストで終わります。
   既定では、死亡したモンスターを次の3区分にまとめます。
   Vanquished Creatures -- キャラクターが倒したモンスター
   Collateral Kills     -- 味方のモンスターによる撃破
   Others               -- その他の死亡（罠、敵対的モンスターなど）

kill_map = friend:you, other:you
        味方とその他のキルをメインの倒されたクリーチャーのリストにマージしま
        す。マージは表示のみを目的としており(ゲームはまだ内部的に3つの別個のリ
        ストを保持しています)、マージされたエントリのキルプレイス(以下を参照)
        の順序が間違っている可能性があることに注意してください。デフォルトは空
        のリストです。

dump_kill_places = (none | all | single)
        このオプションは、Vanquished Creaturesリストで、各殺害場所の表示方法を
        制御します。場所の表示を完全に抑制するには'none'を使用し、既知の(最大5
        つ)のキルプレイスをすべて表示するには'all'を使用します。それ以外の場合
        は、単一のキルについてのみキルプレイスを表示するデフォルトに
        設定します。

dump_item_origins = artefacts, rods
        ゲームはアイテムを見つけた場所を記憶します。この情報をダンプへ記載する
        アイテムを選択します。利用可能なセレクターは、アーティファクト、
        ego_arm、ego_weap、ジュエリー、ルーン、ロッド、スタッフ、ブック、すべ
        て、なしです。複数のdump_item_origins行を使用する場合は、最後の行が有
        効になります。先行する行はすべて無視されます。

        どの項目にも注釈を付けたくない場合は、dump_item_originsをnoneに設定
        し、dump_item_origin_priceを-1に設定します。

dump_item_origin_price = -1
        アイテムの価格がこの金額以上の場合、アイテムの起源はダンプされます。価
        格による選択を防ぐには、これを-1に設定します。

dump_message_count = 20
        キャラクタダンプファイルに表示される最後のメッセージの数。

dump_order  = header,hiscore,stats,misc,notes,inventory,
dump_order += skills,spells,overview,mutations,messages,screenshot,
dump_order += monlist,kills,action_counts
        (順序付きリストオプション)ダンプ内のセクションの順序を制御します。

        2つのオプションのダンプセクションは「turns_by_place」と「
        kills_by_place」です。これらは、ターンが費やされた場所とモンスターがキ
        ルされた場所に関する詳細な統計を追加します。それらを次のようにダンプに
        追加できます。
             dump_order += turns_by_place, kills_by_place

        もう1つのオプションのダンプセクションは「vaults」です。これには、ゲー
        ム内で生成されたすべてのvaultの場所と名前がリストされます。これは、死
        亡、終了、または勝利したときに発生する最終ダンプ(またはウィザードモー
        ド中の通常のダンプ)にのみ含まれます。

dump_book_spells = true
        デフォルトでは、インベントリ内のすべてのランダート呪文のすべての呪文が
        ダンプにリストされます。このオプションがtrueに設定されている場合、呪文
        は非ランダート魔法書に対してもダンプされます。

4-c     注記。
--------------

Crawlは、プレイ中に特定のイベントを自動的に記録できます。これらはダンプファイ
ルまたは遺体安置所ファイルで読み取ることができます。以下は、この動作を調整する
ためのオプションです。
        以下のイベントが記録されます:
        - レベルの増減
        - ダンジョンの階へ初めて入る
        - それまでに習得したものより高レベルの呪文を記憶する
        - 神の信者になる
        - 神を捨てる
        - 苦行を科される、または許される
        - 神から贈り物を受け取る（Xomを除く）
        - 名前のあるオークの仲間が死亡する（Beogh信仰時）
        - 神の力を初めて発動できるようになる
        - ルーン、ゾットのオーブ、アーティファクトを初めて拾う
        - アイテムを識別する
        - OODまたはユニークモンスターを倒す（後述）
        - HPが危険な水準へ達する（後述）
        - 変異を得る、または失う
        - スキルが重要なレベルへ達する（後述）
        - 死亡する
メモを手動で追加するには':'コマンドを使います。

user_note_prefix = <string>
        メモを見つけやすくするために、指定された文字列をプレフィックスとして手
        動で追加しました。現在、このオプションやオプションの末尾にスペースを追
        加することはできませんが、代わりにUnicodeの非改行スペース文字' 'を使
        用できます。

note_items += <regex>, <regex>, ...
        （リストオプション）アイテムを初めて識別したとき、その短い説明が正規表
        現に一致すれば記録します。例:
             note_items += rod,book,acquirement
        アーティファクト（固定、unrand、randart）は、note_itemsに関係なく識別
        時に記録します。

        一致する説明には、menu_colourオプションのメモと同じプレフィックスが付
        いています(例: 「emergency_item」)。

note_monsters += <regex>, <regex>, ...
        （リストオプション）名前がカンマ区切りの正規表現に一致するモンスターを
        記録対象にします。複数行を指定できます。例:
             note_monsters += Klown,orb of fire

note_hp_percent = 5
        HPが最大ヒットポイントのうち特定のnote_hp_percentageを下回った場合、メ
        モが取られます。同じ出来事に基づいたメモの繰り返しを避けるためのコード
        がいくつかあります。

note_skill_levels = 1,5,10,15,27
        これにより、注目すべきスキルレベルが設定されます。これは1行ですが、+=
        を継続として使用できます。

note_all_skill_levels = false
        これは、note_skill_levels = 1,2,...,27のショートカットです。これをtrue
        に設定すると、すべてのスキルレベルが注目に値するとみなされます。

note_skill_max = true
        このオプションを設定すると、スキルレベルの新しい最大値に達するたびにメ
        モが表示されます。 note_skill_maxがtrueで、note_skill_levelsが空でない
        場合、いずれかの基準が満たされるたびにメモが取られます。

note_xom_effects = true
        これにより、Xomが何かを行うたびにメモが追加されます。

note_messages += <regex>, <regex>, ...
        （リストオプション）カンマ区切りの正規表現に一致するメッセージを記録対
        象にします。複数行を指定できます。例:
             note_messages += Something interferes
             note_messages += protects you from harm
        アビスへの追放をすべて記録する場合:
             note_messages += [bB]anish.*Abyss
        ドラコニアンの鱗が変色したとき記録する場合:
             note_messages += Your scales start

note_chat_messages = false
        falseに設定すると、他のプレイヤーからのWebtileチャットメッセージのログ
        が無効になります。 (この設定はオンラインサーバーにのみ適用されます)。

note_dgl_messages = true
        falseに設定すると、他のプレーヤーから送信されたDGLメッセージのログが無
        効になります。 (この設定はオンラインサーバーにのみ適用されます)。


5-  その他。
==================

5-a     すべてのOS。
---------------

mouse_input = false
        mouse_inputオプションを有効にすると、ゲームで特定のプラットフォーム
        (WindowsおよびUnix)でマウス入力イベントを使用できるようになります。マ
        ウスのサポート範囲はプラットフォームによって大きく異なり、端末の設定に
        大きく影響されることに注意してください。

        Unixでは、xtermのncursesで動作するマウスサポートのみが得られる可能性が
        あります(特に、マウスイベントをアクティブにするために、$TERMにncurses
        の「xterm」が含まれている必要があります。xtermのGNU画面でCrawlを実行し
        ている場合、マウスはおそらく機能しません)。

        Windowsでは、Crawlがマウスを使用するには、コンソールのクイック編集モー
        ドを無効にする必要があります(クイック編集はデフォルトで無効になってい
        るため、標準のコンソールを使用している場合は何も変更する必要はありませ
        ん)。 QuickEditを無効にするには、コマンドプロンプトのタイトルバーを右
        クリックし、[プロパティ]を選択して、[オプション]タブでQuickEditを無
        効にします。

wiz_mode = (no | never | yes)
        ウィザードモードオプション(WIZARDコンパイルでのみ利用可能):
          yes   -- ウィザードモードで開始する（スコアは記録されない）
          no    -- ゲーム開始後にウィザードモードへ入ることを許可する
          never -- ウィザードコマンドの使用を許可しない

explore_mode = (no | never | yes)
        探索モードオプション(WIZARDコンパイルでのみ利用可能):
          yes   -- 探索モードで開始する（スコアは記録されない）
          no    -- ゲーム開始後に探索モードへ入ることを許可する
          never -- 探索モードへ入ることを許可しない

char_set = (default | ascii)
        ゲームプレイ画面用にさまざまなプリセット文字セットを選択します。Crawl
        の以前のバージョンとは異なり、これではI/Oエンコーディングが選択されな
        くなりました。

        ibm_glyphs.txt、dec_glyphs.txt、またはold_unicode_ glyphs.txtを含め
        て、組み込まれなくなった古い文字セットを復活させることもできます。

        タイルビルドへの影響は無視できます。

colour.OLDCOLOUR = NEWCOLOUR
        一部の色が読みにくい端末や、黒以外の背景を持つ端末で独自の配色を作る場
        合に便利です。後の規則を優先し、NEWCOLOURは別の色へ再評価されません。
        指定できる色は次のとおりです。
          black, blue, green, cyan, red, magenta, brown, lightgrey,
          darkgrey, lightblue, lightgreen, lightcyan, lightred,
          lightmagenta, yellow, white
        lightgrayはlightgrey、darkgrayはdarkgreyと同じです。例:
          colour.lightgrey = black
          colour.lightcyan = cyan
          colour.yellow    = brown

display_char = <dungeon_character_name : symbol>
        これらのリストも同様に許可されます。

        dungeon_character_nameに指定できる値は次のとおりです。
           wall, permawall, wall_magic, floor, floor_magic, door_open,
           door_closed, trap, stairs_down, stairs_up, grate, altar, arch,
           fountain, wavy, statue, invis_exposed, item_detected, item_orb,
           item_rune, item_weapon, item_armour, item_wand, item_food,
           item_scroll, item_ring, item_potion, item_missile, item_book,
           item_staff, item_rod, item_miscellany, item_corpse, item_skeleton,
           item_gold, item_amulet, cloud, tree, teleporter, space, fired_flask,
           fired_bolt, fired_chunk, fired_book, fired_weapon, fired_zap,
           fired_burst, fired_stick, fired_trinket, fired_scroll, fired_debug,
           fired_armour, fired_missile, explosion, frame_horiz, frame_vert,
           frame_top_left, frame_top_right, frame_bottom_left,
           frame_bottom_right
        多くは名前どおりです。archは店やポータル、floor_magicとwall_magicはレ
        ベルマップで魔法の地図により判明したマス、invis_exposedは浅い水に潜む
        水棲生物や浅い水を歩く透明な生物、wavyは水と溶岩に使います。

        シンボルは文字、またはそのASCII/Unicodeコード(10進数または16進数(先頭
        にxが付く))を使用して指定できます。

feature += <regex> { <symbol>, <magicmap symbol>,
                    <view colour>, <levelmap_magic_colour>,
                    <levelmap_seen_colour>, <emphasised_colour>,
                    <levelmap_emphasised_colour> } ;
           <regex> { ... }
feature -= <regex>, <regex>
        （リスト形式のオプション）<regex>はダンジョン地形の説明に一致する正規
        表現です。'x'コマンドで表示される説明へ一致させます。複数の説明に一致
        した場合は、該当する全地形へ適用します。

        {...}内のリストはダンジョンの特徴の外観を指定しており、一目瞭然です。
        <symbol>は、上記のdisplay_charオプションをオーバーライドしたり、
        文字のサブタイプを区別したりするために使用できます。

        'magic'は常にマジックマッピングを参照します。したがって、
        <magicmapsymbol>エントリは、マジックマッピングによってのみ検出されたフ
        ィーチャにどのシンボルが使用されるかを決定します。

        'emphasised_colour'は、未訪問の石階段を強調表示するために使用される色
        を指します。階段以外のフィーチャの場合、強調色を設定しても何も役に
        立ちません。

        {...}リストの先頭のパラメータは、空白のままにし、プレースホルダのカン
        マを使用することで省略できます。末尾のパラメータは、プレースホルダのカ
        ンマを使用せずに省略できます。

        複数の機能オプション行を使用でき、複数の機能の説明をセミコロンで区切っ
        て同じ行に並べることもできます。

        機能のオーバーライドは-=を使用してクリアでき、正規表現のみを提供します
        (外観は提供しません)。これにより、説明が正規表現と一致するすべての機能
        がデフォルトの外観に復元されます。

        例:
         * 岩壁を赤くする:
             feature += rock wall { , , red }
         * すべての文字セットで金属壁に#を使う:
             feature += metal wall {#}
         * 上り階段を緑、下り階段を赤くする:
             feature += stone staircase leading up {,,,,green}
             feature += stone staircase leading down {,,,,red}

        シンボルは、display_charと同様に指定できます。
             feature += metal wall {#}
             feature += metal wall {35}
             feature += metal wall {x23}
        全員が同じことをします。

mon_glyph += <monster name or symbol> : (<colour> <glyph> | <monster name>) ,
             <monster name or symbol> : <replacement>
mon_glyph -= <monster name or symbol>
        (リストオプション) mon_glyphオプションを使用すると、モンスターの表示に
        使用されるシンボルと色をカスタマイズできます。

        モンスター名または既存のシンボルに基づいてシンボルをカスタマイズできま
        す。たとえば、エルフをEに配置し、エレメンタルをeに配置したい場合は、次
        のようにできます。

             mon_glyph += e : E
             mon_glyph += E : e

        別のシンボル、色、またはその両方を任意の順序で指定できます。さらに例
        を示します。

             mon_glyph += deep elf annihilator : E lightmagenta
             mon_glyph += Xtahua : lightmagenta D
             mon_glyph += large zombie : darkgrey
             mon_glyph += small simulacrum : x

        (:の左側では大文字と小文字が区別されます。)

        別のモンスターを指定して、そのモンスターの基本シンボルと色をコピーする
        こともできます(これは推移的ではありません)。たとえば、スライムのクリー
        チャーの色が逆だと思う場合:

            mon_glyph += slime creature : merged slime creature
            mon_glyph += merged slime creature : slime creature

        「feature」オプションに示されている構文を使用して、コードポイントを使
        用してシンボルを指定できます。 Unicodeコードポイントを使用すること
        もできます。

             mon_glyph += draconian scorcher : x6e9

        単一の_はスペースとして扱われます。実際のアンダースコアが必要な場合
        は、次のようにその前に\を置きます。

             mon_glyph += player ghost : \_

        また、次のようないくつかの「疑似」モンスターを再定義すること
        もできます。

             player
             sensed monster {trivial, easy, tough, nasty, friendly}
             sensed monster
             merged slime creature

        通常は同じ名前のモンスターがない再生可能な種族も、show_player_species=
        trueで使用するために再定義できます。

        モンスターグリフのオーバーライドは、-=を使用してクリアできます。これに
        より、名前付きモンスター (または指定されたグリフのすべてのモンスター)
        がデフォルトの外観に復元されます。 -=には、削除される置換ではなく、モ
        ンスターの名前またはグリフのみを指定します。

item_glyph ^= <regexp> : <colour> <glyph>
item_glyph -= <regexp>
        (順序付きリストオプション)正規表現に一致するすべての項目の記号や色をカ
        スタマイズします。 mon_glyphとは異なり、これは部分的な名前一致です。

        アイテムには、隠し場所の追跡とメニューの色の両方からのタグが接頭辞とし
        て付けられます。したがって、{アーティファクト}またはuseless_itemに色を
        付けることができます。

        複数のルールで1つの項目を変更できます。これは、色とグリフを個別に変更
        する場合に便利です。
            item_glyph += corpse : x625
            item_glyph += poisonous.* corpse : lightgreen

        ルールは順番に適用されるため、後のルールの優先順位が高くなります。

        -=を使用してルールを削除すると、指定された正確な正規表現を使用してすべ
        てのルールが削除されます。その場合は、色やグリフを指定しない
        でください。

pizza = <topping name>
        プレイヤーが好むピザのトッピングのカンマ区切りのリスト。

use_fake_player_cursor = true
        ターミナルカーソルを使用せずに、メインビューでプレーヤーをハイライト表
        示します。これは、描画のために別の場所に移動するためにカーソルをオフに
        してもちらつきがなく、デフォルトでカーソルをオフにすることができること
        を意味します。タイルビルドには影響しません。

show_player_species = false
        キャラクターを種族のメンバーとして表示します。たとえば、あなたがHill
        Orcの場合、'@'ではなく'o'として表示されます。タイルでは効果が
        ありません。

fake_lang = <lang1>[,<lang2>[,...]]
        1つ以上の偽の言語を設定し、指定された順序で適用します(順序は重要です!)
        同じ言語を複数回設定できますが、最終的にはあまり意味がなくなる可能性が
        あります...一度に最大3つの偽の言語を設定できます。

        オプションは次のとおりです:
        (dwarven|jagerkin|kraut|runes|wide|grunt|butt:<n>)それらが何をするのか
        試してみてください。

5-b     DOSとWindows。
------------------------

dos_use_background_intensity = false
        DOSおよびWindowsで、高輝度の職業カラーを実行できるコンソールを使用して
        いる場合は、優れたフレンドブランド化のためにこのオプションをtrueに設定
        します。コンソールがこのオプションを好まない場合は、フレンドリーなモン
        スターが点滅する文字として表示されます(そのような場合には、このオプシ

5-c     Unix。
-------------

background_colour = black
        デフォルトの職業カラーを名前で設定します(デフォルトはBLACK)。これは、
        黒以外の職業色の端末(xtermなど)を使用している場合に便利かもしれません
        が、このオプションはまだ実験段階にあるため、結果はあまり良くない可能性
        があります。

        trueの場合、Crawlは端末にカーソル描画を任せず、レベルマップおよびター
        ゲティング画面に明示的にカーソルを描画します。端末でダークグレー/黒の

        します。 Unix以外のビルドでは、このオプションのデフォルトはfalseです。


6-  Lua。
========

6-a     Luaファイルの読み込み。
-------------------------

Luaファイルは、既存のコマンドに新しい意味を与えたり、(マクロで使用する)新しい
コマンドを作成したりできるスクリプトです。 Luaファイルを使用するには、ユーザー
LuaスクリプトをサポートするようにCrawlをコンパイルする必要があります。Crawlが
Luaをサポートしている場合は、ゲーム内で?Vを押してください。Crawlが表示する機能
のリストには、「Luaユーザースクリプト」が含まれている必要があります。

Luaファイルは、lua_fileオプションを使用してインクルードされます(1行に1つ
のファイル)。

lua_file = <path/name.lua>

Lua関数は、マクロアクションを「===」に設定し、その後に関数名を続けることでゲー
ム内でマクロ化できます。

ウィザードモードのLuaインタープリター (&^T)は、初めて呼び出されたときに、
terp_fileオプションで指定されたすべてのファイルをロードします。

terp_file = <path/name.lua>

これらのファイル内のLuaは、すべてのCrawl Lua内部にアクセスできます(つまり、
cluaではなくdluaのコンテキストで実行されます)。

6-b     インラインLuaの実行。
-----------------------------

Luaコードはinit.txt/.crawlrcで直接使用できます。次の構文を使用してLuaコードを
実行できます。

:単一行のluaコード

<複数行の可能性あり
  Luaコード>

{複数行の可能性あり
  Luaコード}

2番目と3番目のケースでは、区切り文字がそれぞれ行の先頭と行末に出現するという制
限があります。 <>と{}の違いは、コードがいつ実行されるかです。コード{}はすぐに
実行されます。他のLuaコードは、initファイル全体が読み込まれた後にのみ実
行されます。

例:

# Print a welcome message
: crawl.mpr("こんにちは " .. you.name())

<
-- 別のウェルカムメッセージ（LuaコードはLuaコメントを使用）crawl.mpr("
こんにちは")
>

{
function ch_autopickup(it) [ ...本体省略... ] end
}

6-c     条件付きオプション。
----------------------------

Luaを使用すると、同じ構文を使用して(たとえば文字タイプに基づいて) init.txtの一
部を選択的に含めることができます。

例：

: if you.race() == "Mummy" then
autopickup = $?+"/
: else
autopickup = $?+"/!%
: end

オプションは、「options.option_name」を介してluaから参照できます。例えば：

:if string.find(options.autopickup, "!") then
# ポーションが自動取得に含まれている場合の処理
:end

「options.option_name」は、Crawl自体が認識しないオプションにも使用できます。コ
マンドラインのオプション設定（セクション0-b）と組み合わせ、オプションファイル
の条件分岐を制御できます。たとえばコマンドラインで「-extra-opt-first
foobar=true」を指定し、次のように記述します。

:if options.foobar then
# ここに処理を書く
:end

6-d     条件付きオプションに関する注意事項。
-----------------------------------

「開始画面」(セクション1)にリストされているオプションはいずれも条件付きで設定
できないことに注意してください。これは、オプションファイルが実際には2回読み込
まれるためです。1回目はLuaをオフにしてキャラクター作成前に、2回目はLuaをオンに
してキャラクター作成後に読み込まれます。開始画面オプションを条件付きで設定しよ
うとすると、設定した条件に関係なく、オプションファイルの一番下にある値が使
用されます。

上記の注意事項は、「wiz_mode」オプションにも適用されます。条件付きwiz_modeの代
わりに、コマンドラインに「-extra-opt-last wiz_mode=yes」を追加して、新しいゲー
ムをウィザードモードで開始することができます。
